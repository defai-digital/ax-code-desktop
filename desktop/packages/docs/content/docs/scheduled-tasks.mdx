# Scheduled Tasks

A scheduled task runs a prompt for you on a schedule — for example, a daily "summarize yesterday's changes" or a weekly cleanup. When it runs, AX Code starts a new session and sends the prompt on its own.

Each project has its own tasks, and tasks in different projects run independently, so you can schedule one task in one project and several in others at the same time.

## The Scheduled section

Scheduled tasks are listed in the **Scheduled** section near the top of the session sidebar, above your projects. It shows every project's tasks in one queue: tasks that are running come first, then tasks whose last run failed, then the rest in the order they will fire, and paused tasks last. Each row shows the task name, its project, its schedule and how long until it next runs.

- Click a task to edit it.
- Hover a task (or move focus to it) for **run now** and **pause** / **resume**. The **⋯** menu has the same actions plus **edit** and **delete**, and shows the next run time and the last error.
- Click the section title to collapse it. Collapsed, it still shows how many tasks are running or failing and when the next one fires.
- The calendar button at the top of the sidebar opens the section and moves focus to it.
- To hide the section, turn off **Show scheduled tasks** in the sidebar's display menu. While it is hidden, Desktop does not load task lists; the tasks keep running.
- While you search sessions, the list folds away so it does not mix with the search results.

## Create a task

1. Click **+** in the Scheduled section. With several projects, choose the project the task belongs to.
2. Give the task a name.
3. Choose when it runs:
   - **daily** — at one or more times each day
   - **weekly** — on chosen weekdays and times
   - **once** — a single date and time
4. Set what it does: the prompt to send, and the provider, model, and agent to use.
5. Save, and make sure the task is enabled.

Tasks are stored and run by the AX Code runtime (its `/scheduled-task` API), so they also fire when the runtime is up but the Desktop window is closed. A task with several times or weekdays is saved as one runtime task per time/weekday, named like "Cleanup (2/3)"; the sidebar shows those parts as a single task with all of its times, and pausing, deleting or editing it applies to every part. If a part is removed elsewhere (for example from the terminal), the remaining parts are listed separately under their full names.

You can run any task immediately with **run now** to check it does what you expect. The list refreshes when the runtime reports a run, shortly after a task's run time passes, and every few minutes while the window is visible.

## What success looks like

After a run, the task shows when it last ran and whether it succeeded; if a run fails, the error is shown there too. The runtime keeps a bounded run history per task, protects against overlapping runs of the same task, and automatically pauses a task after repeated consecutive failures.

## Keep in mind

Tasks only fire while the AX Code runtime is running. Desktop wakes every registered project's scheduler at launch, again after the runtime restarts, and when you add a project, so tasks also fire in projects you have not opened. If it is down, missed times are coalesced into one catch-up run after restart rather than replaying every missed interval.

Tasks created by older Desktop versions are migrated automatically on first launch after the upgrade. Prompts that were slash commands (like `/review`) and cron expressions outside the runtime's supported subset are not migrated; they are recorded in the migration report (`scheduled-tasks-migrated.json` next to the per-project config directory) so you can re-create them by hand.
