# Runtime pin 7.25.5 → 7.25.7 and SDK pin 2.6.16 → 2.6.17

Date: 2026-10-14

## Outcome

The two independently pinned producer inputs moved to the newest published versions:

- signed runtime: 7.25.5 → **7.25.7** (`config/ax-code-runtime.json`)
- published SDK: 2.6.16 → **2.6.17** (`config/ax-code-sdk.json`, three package manifests, lockfile)

The SDK could not move further: the SDK `2.6.18` tag exists in the producer repository and its
"Publish SDK to JSR" workflow run completed, but JSR does not list 2.6.18 yet, so 2.6.17 is the
newest installable version. Runtime 7.25.7 is published with the SDK 2.6.18 pairing, so the desktop
runs one SDK minor behind its runtime's pairing — the same skew the 7.25.5 pin carried, and the v2
contract is unchanged (below).

## Runtime evidence

- Release `v7.25.7`, published `2026-10-14T23:35:47Z`, carries the four pinned targets, their
  `.minisig` signatures, and the public key `ax-minisign.pub`.
- The published public key is byte-identical to the committed `resources/keys/ax-minisign.pub`
  (SHA-256 `41de2e31510ccfc6f3450d8de1e8ed59481413d00f8a58d65bddbc05042397b2`).
- Every artifact's size and SHA-256 were computed from the downloaded bytes, and each Minisign
  signature verified with the committed key. Each signed trusted comment embeds a digest that
  matches both the computed digest and the GitHub release asset digest.
- Verified content differs from 7.25.5 for every target, so this is a real repin and not a re-tag.
- darwin-arm64 was staged and booted on this machine: `ax-code --version` reports 7.25.7 and
  `serve --hostname 127.0.0.1 --port 51278` answered `/global/health` with `"version":"7.25.7"`,
  `"healthy":true` and all 13 services `running` after the startup interval. The process was killed
  and the temporary profile removed afterwards.

Receipt: [.internal/reviews/release-7.25.7/runtime-verification.json](../reviews/release-7.25.7/runtime-verification.json).

## SDK evidence

- JSR live metadata reports 2.6.17 as `latest`, published `2026-10-14T17:56:20.460113Z`. The
  annotated tag `sdk-v2.6.17` (tagger `2026-10-14T13:55:08-04:00`) resolves to producer commit
  `acc03b6f8558041a4a2b80c921819875933acfe5`; the "Publish SDK to JSR" workflow run
  [38610738024](https://github.com/defai-digital/ax-code/actions/runs/38610738024) completed
  successfully.
- Comparing the installed 2.6.16 and 2.6.17 trees, the v2 and v1 generated clients declare the same
  route URLs (empty diff), and the exported subpath set is unchanged, so no Desktop call site needed
  a change.
- The one behavioural delta is `dist/sse.js`: both bytes of a CRLF pair now count toward
  `sseMaxEventCharacters`, so a CRLF-terminated stream can no longer hold twice the configured frame
  budget. That is a hardening fix inside the SDK's own parser and needs nothing from this
  repository.

## Compatibility

`pnpm-lock.yaml` changes only the SDK dependency: three importers plus the removed 2.6.16 package
entry and the added 2.6.17 entry. No other dependency moved.

## Residual risk

Runtime 7.25.7 does not contain the agent-initiated navigation producer change
(`defai-digital/ax-code` `227ec97a5`), which landed after the release tag. The Desktop bridge for
`operation: "navigate"` committed in `d3992e87` therefore stays dormant until a signed runtime that
carries that producer change is pinned. No published runtime has it yet.

Signed native installation, upgrade, rollback and profile-continuity receipts for this pin remain
part of the next release candidate's evidence, as AGENTS.md requires.
