## Reproduced session-folder data loss and fix

POST /api/session-folders previously treated every error reading the existing snapshot as corrupt/missing JSON and continued saving with no base. A stale client snapshot could overwrite an unread valid layout, including on EACCES when the parent still allowed an atomic replacement.

Isolated fault injection through the actual registered old route reproduced both EIO and EACCES: HTTP 200, a filesystem write and an empty resulting folders map. The fixed handler answers HTTP 500 before mkdir/write/rename and preserves the original snapshot bytes. The reproduction uses an isolated injected filesystem; it does not fault a real disk or touch user files.

Malformed-JSON recovery is now confined to JSON.parse. ENOENT still permits first-save creation; other filesystem read errors propagate. The queue recovers for the next save, which can read and merge a newer disk snapshot while retaining its folders and collapsed state. Explicit malformed/zero-byte JSON recovery and GET corruption reporting remain covered. The existing full-snapshot merge protocol and its independent concurrently open-window limitations are unchanged.

Two regressions failed before the fix; all 13 focused tests passed afterwards. Five new tests cover read failures, subsequent-save recovery, missing-file creation and malformed/zero-byte recovery. Existing concurrency and rename-cleanup mocks now model an explicit ENOENT read instead of depending on a swallowed missing readFile method. No assertion or baseline was relaxed.
