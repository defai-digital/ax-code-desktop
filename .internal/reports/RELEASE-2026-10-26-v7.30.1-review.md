## Reproduced bug and correction

Both actual CLI reviewers identified inconsistent command ownership in useWebMcpPoolProjection. Applying listed views already skips busy/starting renderer rows, but pruning missing native IDs skipped only starting rows. A background list response could therefore reset an enabled busy row while an action was still running, losing its browser state and triggering premature bridge-resume coordination. AgentBrowser command handlers set busy while leaving phase ready, so this is a real state combination.

Add the same current busy guard to missing-view cleanup. Two behavioral regressions fail before the correction and pass after it: an already-busy row survives an empty native list, then is removed after the command completes; a command started during an outstanding poll also retains its row. Both assert no premature bridge resume. The focused projection suite passes all 17 tests. Existing starting-row guards, stale-ID identity checks, polling intervals and command completion behavior remain intact.
