## Integration and fixes

The hotpath stability branch at `d1e538df` and release branch at `aae8024c` were already ancestors of main. Their work, the previously unpushed main history, and the user's reference-index additions were retained and committed. This includes supervision, Streamlit execution and previews, analysis-app handoff, security, lifecycle, streaming and runtime/SDK updates.

Three application regressions were reproduced before fixes:

- A remounted project launcher now records Streamlit readiness and its preview URL while respecting the existing suppression of automatic navigation.
- Optional development-server reads await the response body inside the error handler. An interrupted body no longer rejects discovery and leaves its dialog waiting.
- Returning to a visible window reports a stale event connection as a heartbeat timeout before reconnecting, including a connection that previously survived the healthy window.

The first signed-shadow attempt exposed a fourth issue: runtime 7.27.4 rejects the legacy credential-export `--file` argument. Native qualification now uses the canonical `--output-file` contract. Three qualification regressions failed before the correction; all 11 qualification tests passed afterward. The verified signed macOS runtime exported synthetic isolated references twice with stable canonical auth bytes.

Grok CLI and DeepSeek through AX Code completed bounded read-only reviews. Grok's visibility finding and DeepSeek's discovery-failure lead were reproduced and fixed. The claimed resume/backoff issue was rejected because the retry helper already listens for resume; shared-directory execution is intentionally project-scoped, and managed execution honors custom interpreter/port settings. A separate Grok Streamlit attempt timed out with empty output and is not counted as completed review evidence. Signed review outputs and dispositions are attached to the release.

CodeQL alert 112 was reviewed and dismissed as a false positive, not reported as a code fix. The route intentionally stores bounded JSON preferences at the fixed server-owned `sessions-directories.json` path; no request-selected destination is used. Writes are atomic, the UI normalizes the supported folder fields, and React renders the name as text. The signed disposition records this reasoning. Final-source CodeQL analysis has zero open alerts.
