# SDK 2.6.16 integration

Date: 2026-10-14
Reviewed Desktop baseline: `1075defa`

## Outcome

Update the pinned SDK from 2.6.14 to 2.6.16. The v2 HTTP surface is unchanged and the
type deltas are additive, so no Desktop source change is required. The runtime pin
stays 7.25.3: moving it to the paired 7.25.5 is a separate change that needs signed
artifact receipts (sizes, SHA-256, Minisign) for every platform.

## Published dependency and producer evidence

JSR live metadata reports 2.6.16 as `latest`, published
`2026-10-14T10:51:47.072889Z` (2.6.15: `2026-10-13T10:17:17Z`, 2.6.14:
`2026-10-13T08:14:30Z`). The GitHub annotated tag `sdk-v2.6.16` (tagged
`2026-10-14T10:50:27Z`, unsigned) resolves to producer commit
`c2c2289bdc6d3e148edbe3880a746d36522e7a8a`, and its "Publish SDK to JSR" workflow
[completed successfully](https://github.com/defai-digital/ax-code/actions/runs/38552376791).

The [v7.25.5 release notes](https://github.com/defai-digital/ax-code/releases/tag/v7.25.5)
pair the runtime with SDK 2.6.16 and describe the SDK change as the integrated message
session filter plus `AgentOptions.system` forwarding. That release also stops bundling
AX Engine in the runtime archives; the pinned 7.25.3 runtime is unaffected.

## Compatibility

The pinned dependency in all three Desktop packages is now exactly
`jsr:@defai-digital/ax-code-sdk@2.6.16`; configuration, producer commit, lockfile,
release-contract expectations, and shadow-evidence expectations match. The lockfile
diff contains only this dependency (three importers plus the package entry).

Comparing the installed 2.6.14 and 2.6.16 trees:

- `dist/v2/gen/sdk.gen.js` declares the same 194 route URLs in both versions (empty
  diff), so no endpoint was added, removed or moved.
- Type deltas are additive: a wider `modelID` union (additional AXQ engine ids, `mxfp8`
  variants) and one new optional `iss?: string` on the OAuth callback type. One route
  doc comment about the AX Engine archive was reworded.
- The exported subpath set (`.`, `./v2`, `./v2/client`, `./v2/gen/client`, `./headless`,
  …) is identical; `dist/headless/projection.js` changed for the session filter.

No Desktop call site needed a change, which the three-package typecheck confirms.

## Verification

- `pnpm install` resolves 2.6.16 from npm.jsr.io.
- `pnpm run check:release-contract`: passed (app 7.25.0, SDK 2.6.16, runtime 7.25.3,
  cutover-approved).
- `pnpm run typecheck`, `pnpm run lint`, `pnpm run check:boundaries`,
  `pnpm run check:locales`: passed.
- `pnpm run test`: passed (root 175, electron 516, ui 2036, web 863).
- `pnpm run build`: passed.

## Residual risk

SDK 2.6.16 runs against runtime 7.25.3 rather than the 7.25.5 its release notes pair
with. The v2 contract is unchanged between these SDK versions, so the pinned runtime
remains compatible; the signed native qualification of the eventual release candidate
should still be taken against the runtime the release actually ships, and a runtime
re-pin to 7.25.5 would need its own signed-artifact evidence before it can replace
7.25.3 in the shadow and rollback receipts.
