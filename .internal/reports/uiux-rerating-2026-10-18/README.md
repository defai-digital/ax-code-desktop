# AX Code Desktop comparative UI/UX rerating

Date: 2026-10-18. Assessed product commit: `4f5267e1177e749eb07001c73fc00ee8d9a847dc`.

AX Code Desktop scores **8.4/10**, up from **8.0/10**, moving from fifth to **joint second on the rounded score** in the original eight-interface cohort. This is an expert design assessment of local source and rendered components, not a measured usability benchmark or a market-wide ranking. Under the original rule, differences of **0.3 or less are close**: this does not establish a decisive advantage over OpenHands, Goose, or Cline, or a decisive deficit against OpenCode.

The remaining comparative review is complete. The implementation and Streamlit qualification remain documented in the [implementation report](../supervision-streamlit-2026-10-18/README.md). This report adds assessment and fresh evidence; it changes no product behavior or release state.

## Baseline and method

The original assessment was recovered from the assistant's completed message at `2026-10-18T09:44:20.773Z` in session `01a14e5f-ad5e-7093-8aab-8b176e467222`. Its AX candidate was `d1e538df7496f48a2fa985ef2becb2997aa8f14a`, which **already included v1**: labeled primary navigation, scope disclosure, density controls, and text/icon state badges. Those improvements receive no second credit here.

[baseline.json](baseline.json) preserves the original weights, overall scores, message digest, and recorded reference commit prefixes. No historical per-dimension scores were recorded; none are reconstructed. [inventory.json](inventory.json) binds this assessment to the full local reference SHAs, reviewed source digests, candidate source inventory, and evidence receipts. All seven reference checkouts match the original recorded revisions and are clean. They were not fetched, changed, built, or executed. Orca, Codex, and Pi are outside this fixed cohort; their exclusion is not a rating.

The seven reference scores are **retained baseline anchors**, supported by targeted source reinspection. Only AX receives a new numerical assessment. This avoids implying that every competitor was newly tested under identical runtime conditions. The reference surfaces are OpenCode's GUI, OpenHands' GUI, Goose Desktop, Cline's desktop/shared SDK UI, OpenChamber, Continue's IDE GUI, and Aider's experimental Streamlit browser GUI. Aider's CLI and Cline's other surfaces are not rated by these scores.

The same four user questions organize the walkthrough: (1) how to start a first task, (2) how to understand and respond to a blocking request, (3) how to locate ongoing work and retain context, and (4) how to inspect changes without mistaking them for verified completion. Product breadth, model quality, framework choice, and the mere addition of Streamlit earn no points. Source review can establish available affordances and state handling, but cannot measure task completion time or novice comprehension.

## Next improvement backlog

These items explain why the current score stops below 9; they are not requirements retroactively added to the completed v2 change.

1. **Verification evidence in review.** Consume an explicit runtime-owned result with source, run identity, time, and passed/failed/not-run/unknown states. Keep changes present separate from verification passed. Accept when each state and stale/missing evidence is demonstrated without inventing success or duplicating runtime ownership. Propose any required contract change through the existing PRD/ADR process.
2. **First-task guidance.** Connect runtime readiness, selected project, provider/model readiness, and the first useful prompt through clear next actions. Keep advanced paths available. Accept when a clean-profile walkthrough reaches a real first task, preserves user choices, and shows recovery from missing setup without dead ends.
3. **Small-window hierarchy.** Reduce header height and nested-scroll burden, and explain overlapping tool destinations. Preserve labeled keyboard access and user preferences. Accept through actual full-workspace walkthroughs at narrow widths and 200% zoom, with visible task content as well as reachable controls.
4. **Independent usability and accessibility validation.** Run the same four tasks with representative users and complete-app keyboard/screen-reader checks. Measure completion, wrong decisions, recovery success, and time to locate evidence. Freeze reference revisions and environment before a new comparative benchmark; set a future score from results rather than treating 9/10 as a shipping requirement.

Prior Grok/DeepSeek advisory and Grok/Codex implementation review dispositions remain in the [implementation report](../supervision-streamlit-2026-10-18/README.md#validation-and-review). This numerical rerating is the current assessor's conclusion, not a consensus score from those reviewers. Grok's timed-out implementation passes remain unqualified.
