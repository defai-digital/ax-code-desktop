# AX Code Desktop v7.29.2 advisory journey investigation

The six original failures included a reproducible product layout defect and several fixture/harness defects. The final source `3de26b91fb262fc9e7dbcc06ee280dd5b890b34a` passes all 11 Desktop CI jobs and all 18 native journey groups across macOS, Windows and Linux, with zero failed journey results. The committed continue-on-error policy was not weakened; actual result files were checked independently of the workflow's green conclusion.

Fixes are committed and pushed on `fix/advisory-browser-journeys`. They are not merged into main or published in a new release. The published v7.29.2 tag remains `0a8296ce1dc69d5bb4fa63bb00ca5171cf7dca2d`; all 94 published asset sizes/digests were read back unchanged.

## Original six failures

| Failure | Confirmed cause and correction |
| --- | --- |
| macOS Browser: W7 selected ses_e2e_other | At a 1024x685 renderer viewport, expanded controls collapsed the native page to zero height. Both retained native pages reported visible=false. Bound and scroll the controls independently so the native region remains visible. |
| macOS Tasks: w6-first completion | The growing call strip caused the same zero-height region. Enrollment stayed on while visibility-gated execution correctly waited. Preserve visible page space rather than bypassing that safety gate. |
| Windows Browser: agent enrollment | The stub compared path spelling case-sensitively, while native ownership uses case-insensitive Windows identity. Use the shared identity function for comparisons, while preserving existing path payload/event spelling. |
| Windows Tasks: provider enrollment | The same fixture endpoint rejected the native normalized directory. A spawned-runtime regression returns 404 before the correction and 200 afterward; POSIX case sensitivity remains intact. |
| Windows Supervision: missing Settings | The journey acted immediately after reload, before the control was available. Wait for the Settings control and then for its view before Chat navigation. Stderr also revealed an independent transient EPERM replacing settings.json; add bounded Windows atomic-replace retries without unlinking the valid destination. EPERM is not claimed to cause the missing control. |
| Linux Browser: screenshot timeout | W7 state/memory checks and the main screenshot had completed; the next operation attempted a detached, hidden guest screenshot. Select and observe each guest visible before capture. The two evidence switches remain separate from the 50 stress switches. |

Both macOS failures reproduced locally with the exact original errors using real native guests and a 1024x685 renderer viewport. The page region measured 0px before the layout fix and about 207px after it. Normal-viewport baseline browser/task/supervision journeys passed, which explains why those baseline runs alone missed the defect.

## Additional findings and fixture corrections

Development startup argv included Electron's app-entry directory. Treating it as a user-requested project could deliver a delayed project-open event and replace the fixture selection. An actual Electron probe confirms defaultApp=true and the executable/entry argv shape. Ignore those launch arguments only for the matching development launch; preserve plain file-open and packaged project arguments. The new regression fails before the fix and 13 focused open-path tests pass after it. Packaged starts do not use defaultApp.

Review and Browser are separate surfaces at a small viewport. The credential-identity regression now navigates Workspace/Review normally and observes fresh evidence on each surface, retaining all attribution/redaction assertions and original W3/W4/W6/W8 action budgets.

UI refs expire after another inventory snapshot or action and reject a changed accessible name. The switcher stops on the matching inventory page and invokes its current ref immediately. It also waits for the specific waiting-page announcement before using a Needs you button that already existed for unrelated requests. Ref lifetime checks remain strict.

An investigation mistake initially lowercased serialized Windows path payloads as well as comparison keys. A new spawned-runtime regression catches this in /path, archive write records and the actual SSE session.updated envelope. The fixture now normalizes identity only for comparisons, preserving its existing wire spelling. Twenty-three scenario tests and nine UI-client tests pass. The Archive journey compares semantic path identity while retaining captured request records.

A Windows failure diagnostic captured a page-control name changing solely because a native projection lowercased the directory. The UI now retains the registered project path spelling for display while keeping native command identity unchanged. The regression fails before the correction. Archive eligibility also settles asynchronously; the journey now observes the final disabled state within the existing ten-second semantic deadline instead of asserting it immediately after opening the menu.

Independent regressions prove that Windows drive/UNC aliases previously created different directory child stores. Views using another spelling could read a different message cache or retain stale live sessions. Child stores now share the existing lexical identity, preserve the first stored spelling, and apply alias-aware pinning, updates and disposal. Routing retirement removes matching Windows aliases and their message indexes while preserving other directories. POSIX case remains significant. The focused child-store/provider/routing suite has 44 passing tests.

The transient two-step rather than three-step Windows recap did not reproduce in run 40228974684, before the child-store correction. That run passed all 18 journey groups but failed the separate Linux opening-animation smoke (15-second decode timeout, zero frames). Neither case aliases nor timing ties are asserted as the proven cause of that transient recap observation. Its failure diagnostics and strict three-call assertion remain in the harness; the final run below separately verifies the corrected source.

Windows replacement retries cover only EPERM/EACCES/EBUSY, at most six rename attempts with 25/50/75/100/125ms waits. Four regressions fail with the old single-rename behavior. Exhaustion cleans only the temporary file and propagates the error; a permanent error or non-Windows failure is not retried.
