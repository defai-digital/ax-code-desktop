A dependency-ready prototype is not possible under current Desktop rules. Integration waits on canonical package delivery. The revised plan is the right sequence. Commit `912c8f92c4d66d0ad8a2887251c3325bbf8b5718` is a real worker API for preview, strict hunk apply, patch chunks, and duplicate comparison. It is still a private workspace package, so Desktop cannot depend on it yet.

**API to UI**

Pierre is synchronous and is the single source for paint, `getFileHunks`, navigation anchors, revert, and Git stage matching (`additionStart === newStart`). Wasm `diff()` is async, allows one in-flight call per engine, does not queue, and cancellation kills the worker. `getFileHunks` runs inside `useMemo`. An empty array renders as no list, so a rejected or in-flight Wasm result has to stay distinct from "no hunks" or error and oversize files disappear.

The preview does not supply Pierre's `hunkSpecs`. It uses four lines of context and includes empty ranges. Stage buttons and aria labels assume Pierre headers and git's hunk split. One shared snapshot cannot drive the review list while Pierre still paints, because the painter parses on its own. A read-only integration is a shadow snapshot for parity, keyed by owner and content hash, with host-side serialization, cancellation, and discard when the revision changes. It should not feed navigation, revert, or stage.

Files over 16 MiB, 4,096 hunks, or 200,000 lines need the existing too-large path. `normalize: true` rewrites coordinates while leaving addition and deletion counts raw. On-disk CRLF revert and git `newStart` matching need the raw diff. The Markdown CRLF lex fix stays out of this migration. The renderer needs the browser entry, a module worker, `application/wasm`, and an explicit CSP Wasm-compile token under ADR-018. The AX Wiki export CSP can stay unchanged. Cold start, multi-file serialization, and terminate-on-abort cost are unmeasured. No speed claim follows from this API.

**Subset and reverse apply**

`applyHunks(before, hunks)` applies forward with exact coordinates, counts, and source context. Revert today is Pierre `diffAcceptRejectHunk(..., "reject")`: the full file, one hunk restored, every other change kept. The Wasm equivalent is the complement applied to the before snapshot. The README requires rebasing `newStart` for any subset and does not export a rebase helper. A Desktop rebase would be a second kernel. Context checks reject a bad rebase when the context misses. They do not replace a canonical, tested rebase. `applyPatch` folds whitespace and punctuation and is the wrong contract for revert. Empty ranges can shift indexes relative to Pierre, so index identity is unsafe until segmentation matches. The documented exact round-trip is the full hunk list, including a missing final newline. Subset revert stays on Pierre until the canonical package can reconstruct one rejected hunk and match Pierre's bytes on CRLF, no trailing newline, Unicode, and empty ranges.

**Packaging**

`private: true`, `workspace:*` on `@ax-code/util`, and gitignored `dist/` and `wasm/` mean there is no installable artifact. Desktop cannot import `../ax-code`, ignored build output, or a vendored copy of the kernel. The browser build has to keep Node-only util out of the renderer, by inlining a browser-safe subset or pinning an exact published util. Delivery is a registry tarball at an exact version, like the SDK pin, containing `dist/`, `wasm/`, and `NOTICE`, with the BSD jsdiff notice carried into Desktop's `NOTICE` in the same change. Electron and the Vite dev server must serve the worker and Wasm with the right MIME. This review does not authorize publication. Desktop CI should not grow a Rust or wasm-bindgen toolchain to build this package.

**Measurements before replacing Pierre**

On a frozen corpus (CRLF, missing final newline, emoji, empty sides, binaries, oversize, many hunks), record hunk-boundary equality against Pierre and against `git diff`, including the `newStart` match rate and duplicate `newStart` collisions; byte equality of canonical single-hunk revert against `diffAcceptRejectHunk`; full apply round-trip on Desktop snapshot bytes; worker cold start and per-file latency under one in-flight call; and Wasm instantiation under the packaged CSP. A segmentation mismatch usually hides the stage button. A shared `newStart` can still bind the wrong git hunk. Replace the painter and the actions only after those checks pass. Until then, Git staging and revert stay on Pierre.

**Answer**

Current rules block a dependency-ready prototype. The first deliverable is an owner-published, independently installable, exact-pinned artifact whose public API includes subset rebase or single-hunk reverse reconstruction. The following Desktop step is a read-only shadow worker, still outside the action path.
