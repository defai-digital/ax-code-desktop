Earlier Grok and Muse approved replacing marked.lexer(text) with new marked.Lexer().blockTokens(normalizedText), caching normalized text and offsets, plus lastIndexOf instead of split for last fence line. Both reviewers said a fresh lexer isolates its queue. Local verification found this incomplete: const a=new marked.Lexer(), b=new marked.Lexer(); a.options===b.options, a.options.tokenizer===b.options.tokenizer, and a.options===marked.defaults are all true. The shared tokenizer has lexer backreference. Its last undrained queue can retain text globally. Final patch now uses:
const lexer = new marked.Lexer({ ...marked.defaults, tokenizer: undefined })
tokens = lexer.blockTokens(normalizedText.slice(stablePrefixLength))
lexer.inlineQueue.length = 0
The installed public constructor chooses options.tokenizer || new Tokenizer, then stores tokenizer.lexer=this. With independent options and undefined tokenizer this creates an invocation-owned tokenizer. On throw, existing whole-text fallback is retained; no shared root retains this local cycle. Production only consumes type/raw. No global marked.use/options usage exists in this repository. Added regression constructs other=new marked.Lexer(); other.blockTokens('Other **message**'); snapshots its inlineQueue, invokes the production builder, then requires other.options.tokenizer.lexer===other and its pending queue unchanged. The original CRLF normalization and block semantic parity checks remain. No WASM was adopted; unpublished sibling diff-wasm remains duplicate-only and is not consumed.
