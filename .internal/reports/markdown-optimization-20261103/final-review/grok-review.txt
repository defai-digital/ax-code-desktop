The lifetime claim holds for this callsite. `new marked.Lexer({ ...marked.defaults, tokenizer: undefined })` passes an object that is not `marked.defaults`. The installed constructor treats `tokenizer: undefined` as missing (`options.tokenizer || new Tokenizer`) and writes that new tokenizer, `tokenizer.options`, and `tokenizer.lexer = this` only onto the fresh pair. `inlineQueue` is the lexer’s own `[]`, so `lexer.inlineQueue.length = 0` touches this invocation alone. The cycle is lexer → options → tokenizer → lexer, and nothing in that sequence assigns the tokenizer back onto `marked.defaults`. If `blockTokens` throws, the queue clear is skipped and the cycle is reachable only from the dying frame. The shared-root failure mode is gone on this path, including the throw path. `blockTokens` fills `type` and `raw` before any inline drain, so clearing the queue leaves those fields intact.

No separate production correctness defect follows from this patch. Stock block rules are the shared non-global module tables, so this path does not leave a `lastIndex`. The shallow copy still shares `extensions` and `hooks`; with both null and no `marked.use` or `marked.options` in the repo, that sharing has no effect.

The regression is its own process-lifetime root. `other = new marked.Lexer()` still installs `other`’s tokenizer on `marked.defaults`, and its `blockTokens` call leaves that queue undrained on purpose. The assertions detect retargeting of that shared tokenizer, and after the test `marked.defaults.tokenizer.lexer` still points at `other`. A later bare `new marked.Lexer()` or `marked.lexer()` in the same worker reuses it.

This covers the shown constructor, the queue clear, and the regression, assuming the whole-text fallback uses the same detached construction. A fallback that still calls the bare constructor would root that fallback lexer on `marked.defaults`. CRLF normalization, block parity, and skipping WASM are unchanged.
