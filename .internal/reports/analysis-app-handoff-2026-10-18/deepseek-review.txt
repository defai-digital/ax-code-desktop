## Concrete bugs and fixes

**1. HIGH — Double launch: claim dedupes listeners, not runs.** `claimAnalysisAppRun` only prevents two *toolbars* from handling the same event. A second click dispatches a fresh cancelable event while the first handler still awaits `getProjectActionsState`; both then enter `runAction`, whose config read/save happens before it touches run state. Fix: a synchronous `pendingRef` keyed by `${sessionId}\0${entrypoint}`, set before the first `await`, checked at handler entry, cleared in `finally`. Nothing in the shown code provides this.

**2. HIGH — Run card is enabled on mobile where no controller exists.** The toolbar early-returns on `(!allowMobile && isMobile)`, but `AnalysisAppCard`'s `disabled` only checks `!directory || activeSessionId !== sessionId`. Every mobile click is unclaimed and shows an error toast. Fix: apply the same gate to the card (distinct, localized reason), or register a mobile-capable handler.

**3. MEDIUM — Directory binding mismatch produces a dead Run button.** The card sends the session/worktree directory; the controller claims only if `normalize(detail.directory) === normalize(normalizedDirectory)` (its own project directory). When a session's attached worktree differs from the focused project directory, the claim is rejected and the card shows `noActiveDirectoryForAction` even though the directory is active. Fix: include the same directory equality in the card's `disabled` computation, or resolve the owning directory by session and route `runAction`/terminal/preview to `request.directory`; use a separate "run unavailable in this view" message.

**4. MEDIUM — Silent no-op for running-without-URL.** `else if (running)` with no `previewUrl` (status `starting`, or URL not yet captured) executes nothing; `status === "stopping"` with a URL likewise does nothing with no feedback. Fix: open/focus the run's terminal tab or show starting progress; suppress only when reopening an already-open preview.

**5. MEDIUM — First click never offers Prepare.** The `runAction(action, false, …)` branch ignores the resulting status. If the run transitions to `setup-required`, the recovery path — `setStreamlitDialog` — only runs on a *second* click. Fix: after the awaited run, re-read the run entry and open the dialog when `setup-required` or `failed`.

**6. LOW — Claim can throw and be misreported.** `JSON.stringify(detail.artifact)` throws on circular objects, BigInt, or a throwing `toJSON`; the error escapes the listener, the event stays unclaimed, and the card reports "no active directory". Fix: validate `detail.artifact` fields directly instead of the serialize/parse round-trip, or wrap in try/catch → `null`.

**7. LOW — Skill: existing manifest gap.** "Do not overwrite an existing requirements file" leaves no way to declare Streamlit when `requirements.txt` exists without it; explicit Prepare then cannot install it. Fix: permit appending missing pins (or a dedicated extra-requirements file the setup path reads), and require confirming Streamlit is declared before emitting the fence.

**8. LOW — Non-Streamlit frameworks have no delivery path.** The skill says honor an explicitly requested or existing framework, but Deliver defines only the `streamlit` handoff. Fix: add an explicit branch — link the entrypoint, give run instructions, emit no `ax-code-app` fence.
