## Verified fixes

1. **Project snippets during A → B → A loading.** The returning caller joined A's existing single-flight request without publishing A's loading/list state, leaving B's snippets displayed under A. An A failure left the foreign list indefinitely. Publish the active project's own cached/empty list before joining and restore only that project's list on failure. The before-fix regression fails on B's foreign payload; the fixed behavior clears it immediately.
2. **Oversized snippets list flushing unrelated snapshots.** Inserting an uncacheable response into the bounded cache evicted other projects before eventually evicting itself. Bypass insertion for oversize responses, invalidate only that project's old snapshot, and still publish its current view. The regression proves another project's fresh snapshot remains a cache hit; it fails before the fix.
3. **Project removal during a snippets read.** Registry cleanup can revoke a read without starting another load. Clear the active view's loading state at invalidation; its late response is rejected by owner identity. The regression fails before the fix on a stuck loading flag.
4. **Replacement store subscription ownership.** A registry observer can recreate a directory synchronously during disposal notification. Old disposal then fetched and removed the new disposer, disabling retention; disposeAll also cleared the new subscription registration after notification. Finish old ownership cleanup before callbacks/notification and reset all old manager maps before recreation. Two regressions fail before the fix: replacement content does not evict, and a detached replacement can re-arm a sweep timer. Both pass after the ordering correction.

The new release also updates the shadow-evidence test's expected Desktop version to 7.30.2. Its runtime and SDK expectations remain 7.30.1 / 2.6.53. The prior literal-version failure is preserved rather than treating it as a baseline exception.

Only public-facing review summaries are exported; raw model transcripts remain operator-local.

## Animation playback qualification follow-up

The initial candidate failed native animation playback on macOS; an unchanged-source run passed macOS but timed out on Linux ARM64. A local diagnostic captured Chromium AbortError: background video was paused to save power. The same ASAR fixture with background throttling disabled only for the temporary animation WebContentsView played all six sampled clips through 72 frames and still respected reduced motion. The controller now disables background throttling for that overlay; normal completion or the unchanged six-second production deadline destroys its contents. The test asserts this setting alongside sandboxing, while existing timeout/disposal tests verify the unthrottled contents are closed. Initial workflow/log evidence remains preserved; the changed candidate requires fresh full qualification. Electron documents the visibility implications of backgroundThrottling at https://www.electronjs.org/docs/latest/api/browser-window#page-visibility.
