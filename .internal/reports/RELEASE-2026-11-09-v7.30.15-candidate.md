## Reproduced read-limit defect

The text route checked descriptor size against 50 MiB, then called unbounded FileHandle.readFile. A concurrent writer
could grow a file after that check and force a read beyond the limit. A regression uses a real temporary file and
file descriptor, grows it after stat, and expects HTTP 413. Before the fix the full oversized sparse file was read
and decoded, resulting in HTTP 400; it was not rejected by the size limit.

Capped text reads now use chunks from the same descriptor, probe at most one byte beyond the cap, and close the
handle on every path. Oversized reads fail before text decoding. Existing raw-download behavior is preserved.
The focused route suite covers ordinary text, binary rejection, missing paths, existing size checks and this growth
race. The regression fails before the fix and passes afterwards; all 68 route tests pass.
