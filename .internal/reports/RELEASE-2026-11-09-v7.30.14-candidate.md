## Reproduced defects and fixes

1. Closing an inspector left keyboard focus on its now-hidden return button. A new behavior test failed before
   the fix. Focus now returns to the enabled conversation textarea, or an available button, while retaining the
   conversation DOM and unsent draft. The native workspace journey also checks the focused composer on return.
2. Skill catalog reads checked a pathname with lstat and reopened it with readFile. A deterministic replacement
   after lstat returned private contents before the fix. Git worktree diff and discovered favicon reads had the
   same check/reopen pattern. All three use a shared checked handle with no-follow/nonblocking flags where supported,
   inode/device identity, canonical path/root checks, bounded allocation/read and unconditional handle closure.
   Tests cover file replacement, growth after stat, byte limits, root containment and ordinary reads.

The GitHub worker-origin finding refers to a dedicated module Worker, not a window message listener: only the creating
DiffParseClient holds its channel, and the result is structured-clone data. Dedicated-worker messages have no useful
window-origin authentication contract. The trace code-construction finding refers to an isolated developer harness
whose predicates come from local constants, arithmetic fixture counts and JSON.stringify string literals; it accepts
no network/user predicate. Review these contexts against the final source rather than adding a window-origin check
that would break packaged workers or claiming scanner findings are automatically exploitable.

3. Actual hosted journey files exposed the same W8 checker failure on macOS, Windows and Ubuntu despite green
   advisory workflow steps. The bundled native API expects an object; the checker double-encoded it as a string,
   and its mock incorrectly modeled that old string contract. The corrected behavioral mock fails before the
   one-encoding fix and passes afterwards, retaining receipt integrity and credential-redaction assertions.
   Native project-browser tasks also exercise the independent checker and subsequent W3/W4/W6 flows.
