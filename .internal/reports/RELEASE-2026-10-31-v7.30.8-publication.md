## Retained attempts and auxiliary limitation

The first startup fixture failed because Chromium blocking did not stop the SDK event stream fetched through the main-process bridge. It was rejected and replaced with availability control at the isolated stub runtime HTTP server. The next source's scan identified file/network data-flow findings in the new test script; the final source constructs a bounded loopback URL and writes validation-only receipt fields. Final scanning confirms those findings are closed without dismissal. Superseded workflows and rejected artifacts are recorded separately in qualification-attempts.json and the operator attempt directories; they are not counted as qualification.

Wiki update was attempted with the installed runtime and failed because the existing external model configuration selects unavailable alibaba-token-plan/qwen3.8-max. The failed refresh was recorded, and the existing external model settings were left unchanged. This auxiliary limitation does not block verified publication.
