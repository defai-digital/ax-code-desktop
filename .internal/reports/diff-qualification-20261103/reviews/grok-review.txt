Two conversions appear, and neither is a diff kernel. `patchText` rewrites unified headers only: a canonical one-based empty range becomes `start - 1`, so an empty old file is `-0,0`. `applyHunks` still receives engine hunks. For one whole-hunk reject, `newStart = oldStart + sum of included (newLines - oldLines)` is the line map for applying that subset to the original snapshot. Equal inter-hunk regions keep the old anchors valid, and the engine still validates the apply. This run’s matching spans leave no room for a repair branch. A future mismatch should fail the request.

Prototype shape: inject the published module, or a double with the same contract. Build metadata with `processFile` in the renderer and pass that object to FileDiff. Apply from the same revision’s canonical hunk list. Keep header encoding and `newStart` adjustment as two named adapters, with `count === 0` covered on both. On limit, abort, or mismatch, use an explicit fallback. Do not vendor canonical source or retune spans to force equality.

Production remains blocked on these gaps:

- CI must install a released, pinned artifact. This report hashes `node.js` only; bind the wasm bytes, package version, and Pierre version. A release requirement is a gate.
- The probe never leaves Node. Packaged Electron CSP, in-flight cancel, timeout, and worker restart are outside these files. Synchronous `processFile` is not aborted with the worker. The shared result has to name realms: postMessage can carry canonical hunks; build the Pierre object where FileDiff runs.
- No revision token or late-response discard is tested. Render, navigation, and actions can still observe different generations. Use one generation even though these spans matched.
- Only one whole-hunk reject is covered. Multi-hunk reject, accept, and line-level reject are untested. Pierre plus the rewritten apply is the right oracle for current FileDiff behavior; an engine apply-by-index would remove the delta math from Desktop.
- Dense 50k-line input throws `Diff resource limit exceeded`. A silent Pierre fallback on those unchecked cases can diverge. The fallback must be visible and tested.
- These scripts are not packaged tests. They reach Pierre through a relative `node_modules` path, and they do not record that the `parseDiffFromFile` arguments match FileDiff.
