## Review and reproduced fixes

Muse CLI 1.4.9-R6297.1 completed an initial updater review and two follow-up reviews of the proposed fixes, all with exit code 0. Writes, shell and web tools were disabled. Grok CLI 1.0.60 completed a bounded PartMap/batching/materialization review with exit code 0, one turn, and zero tool calls. Completed text and dispositions are in `.internal/reviews/release-7.26.1/` and signed release attachments.

- A refused downloaded installer no longer leaves Desktop running with a stopped server/runtime. Services stop through the actual quit coordinator. Native staging errors and synchronous installer failures clean up temporary listeners promptly; background check errors after handoff no longer end the observer; simultaneous install requests share one attempt.
- Ordinary app quitting is no longer mistaken for an update installation start. The observer uses Electron's native `before-quit-for-update`, and requests during normal quit cleanup are refused.
- Forking a mutable PartMap now relinquishes parent ownership of shared buckets. Subsequent parent writes cannot corrupt a published child or make its count disagree with its entries. Normal publication from a sealed source retains the sharded copying strategy.

Snapshot corruption and the ordinary-quit false positive were reproduced before correction. Regression coverage includes colliding message IDs, repeated forks, untouched shared buckets, synchronous install signals, emitted/thrown errors, listener cleanup, silent refusal, duplicate requests and the actual quit coordinator.

Grok independently confirmed the PartMap defect. Its proposed transactional batch rollback was not adopted: existing tests require per-event isolation, valid deltas must survive malformed neighbors, and production dispatch treats non-delta events as barriers. An observer failure does not invalidate already reduced streaming data.

Muse's follow-up confirmed the two updater defects were fixed, then exposed a candidate regression where an unrelated background wrapper error could prematurely end native staging observation. This was reproduced and fixed by separating synchronous wrapper failure observation from native staging errors. The initial candidate was superseded, its unfinished shadow run cancelled, and its CI/partial native evidence was not reused. Further existing policy limits remain: the 30-second start-observation deadline does not cancel a native install already staging, and unbounded service shutdown can block quitting. These remain documented limits and are not counted as fixed. An install-start signal is not proof that the new application has finished installing. This release also includes accumulated main-branch work documented in `desktop/CHANGELOG.md`.
