## WP4: MCP form elicitation, end to end

A minimal stdio MCP server exposed one tool that sends `elicitation/create` (form mode: an `environment` enum and a
`notify` boolean). It was configured in the test project's `ax-code.json`, trusted with `ax-code mcp trust`, and a
`deepseek-flash` session was asked to call the tool (four short model calls in total).

- Manual mode: the question card rendered both fields; answering production and Yes returned
  `{"action":"accept","content":{"environment":"production","notify":true}}` to the server, with a real boolean.
- Dismiss returned `{"action":"decline"}`.
- Autonomous mode: no card appeared and the server received `{"action":"decline"}`, as ADR-204 decides.

Two Desktop gaps found and fixed in "fix(ui): honor fixed-choice questions and explain untrusted project MCP
servers":

- The question card offered "Other..." on enum and boolean fields although the runtime sends them with
  `custom: false`; a typed answer would hand the server a value it never offered. The card now hides it. Re-run:
  no "Other..." option, and staging/No returned `{"environment":"staging","notify":false}`.
- A project-configured server reports `needs_trust` and refuses `POST /mcp/{name}/connect` (403) until the runtime
  CLI trusts it; there is no HTTP route for that. The MCP page showed the state as a grey, unexplained label and now
  shows a warning card with the `ax-code mcp trust <name>` command.

The test sessions were deleted, the server was untrusted again and the test configuration removed.

## Residual risk

- Desktop sessions run autonomous by default ("Auto"), and in that mode every MCP elicitation is declined without
  telling the user; the form only appears in Manual mode. Surfacing a declined elicitation needs a runtime signal
  (for example an event when a request is declined), which is an AX Code decision.
- Trusting a project MCP server still needs the CLI; a GUI trust action needs an AX Code route and its own trust
  decision.
- The trust state is read from the runtime process environment; the Hooks page explains it but cannot change it.
- Signed native installation, upgrade, rollback and profile-continuity receipts for this pin remain part of the next
  release candidate's evidence, as AGENTS.md requires.
