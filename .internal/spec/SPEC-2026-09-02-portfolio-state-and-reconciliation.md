# SPEC: Portfolio State and Deterministic Reconciliation

## 1. Ownership

AX Coder is authoritative for project registration, desired state, contract references, exception workflow, portfolio
budgets, and product leases. AX Code is authoritative for coding execution. A disposable AX Coder projection may index
AX Code events, but it cannot assert that work ran or completed without owner evidence.

## 2. Minimum records

External inputs are validated with versioned Zod schemas. Identifiers are opaque, immutable strings generated by the
service. Records include schema version and created/updated times.

| Record              | Required fields                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------- |
| ProjectRegistration | ID, canonical path, display name, default branch, runtime profile, trust fingerprint        |
| ProjectDesiredState | project ID, revision, priority, automation tier, outcome, budgets, concurrency, pause state |
| ContractRevision    | ID, project ID, parent, content hashes, approval state, actor reference                     |
| ProjectObservation  | project ID, source, cursor, observed version, bounded summary, evidence references          |
| ManagerDecision     | ID, causation IDs, contract revision, outcome, authority, idempotency key, model provenance |
| Dispatch            | ID, decision ID, worker task/run references, state, idempotency key                         |
| Exception           | ID, project ID, kind, severity, evidence, required actor, expiry, resolution                |
| Lease               | resource, owner, fencing token, acquired time, heartbeat, expiry                            |
| BudgetLedger        | scope, period, deterministic counters, warning and hard caps                                |

Raw credentials, complete prompts, transcripts, tool output, repository files, and screenshots are forbidden. Store
bounded redacted summaries, hashes, and references to owner artifacts.

## 3. Reconciliation

Reconciliation is a pure desired-versus-observed decision followed by a separately persisted effect. Its bounded
outcomes are `no_op`, `wait_for_worker`, `refresh_projection`, `dispatch_approved_task`, `request_manager_decision`,
`request_human_decision`, `pause_project`, and `mark_project_complete`.

Every wake has stable causation IDs. Identical input revision and cursors produce the same decision key. Persist the
decision before dispatch. After an unknown side-effect outcome, query AX Code by idempotency key before retrying.

Primary wakes are event-driven. The default ten-minute sweep reads cursors and lightweight health only. Unchanged
cursors and desired revision must yield `no_op` with zero model calls and zero repository scans.

## 4. Leases and budgets

One fenced manager lease exists per project and one mutation lease per worktree. A stale owner cannot commit a later
transition. Budget caps cover model calls, tokens, wall time, steps, retries, workers, and writers. Caps are evaluated
deterministically before effects; exhaustion pauses and raises an exception.

## 5. Recovery and tests

SQLite transactions persist state transitions and cursor advancement atomically. On restart, reconcile expired leases,
pending effects, unknown outcomes, and cursor gaps before new dispatch. Test duplicate delivery, crash before/after
persist and effect, concurrent leases, stale fencing, no-op sweeps, budget caps, contract drift, and global pause.
