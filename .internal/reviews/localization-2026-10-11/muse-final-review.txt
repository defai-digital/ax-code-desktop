### 1. Blocking — `formatPluralMessage` has no `.other` fallback

[store.ts](/Users/akiralam/code/ax-coder-old/desktop/packages/ui/src/lib/i18n/store.ts)

```ts
formatPluralMessage(dictionary, locale, key, count)
```

builds `` `${key}.${category}` `` directly from `Intl.PluralRules(locale).select(count)`, which can return `zero/one/two/few/many/other`. `formatMessage` then falls back to the raw key string if neither the translation nor `en` has that exact key. English only exercises `one/other`, so any locale needing `few/many/etc.` (e.g. Russian) shows `common.itemCount.few` literally unless `en` happens to define all six keys.

Fix — fall back to `.other` before giving up:

```ts
export function formatPluralMessage(dictionary, key, count): string {
  const category = new Intl.PluralRules(locale).select(count)
  const exact = `${key}.${category}` as I18nKey
  const other = `${key}.other` as I18nKey
  if (dictionary[exact] ?? enDict[exact]) return formatMessage(dictionary, exact, { count })
  return formatMessage(dictionary, other, { count })
}
```

Also add a CI assertion that `en` defines `common.itemCount.other`, or that every `common.*` plural base has an `.other` key.

### 2. Non-blocking — renderer discards valid main locale on bad format tag

[store.ts](/Users/akiralam/code/ax-coder-old/desktop/packages/ui/src/lib/i18n/store.ts), `parsePreferences`.

If `state.locale` is valid but `state.formatLocale` fails `new Intl.Locale(...)`, the `catch` falls through to the locally resolved locale instead of keeping main's locale. Main's tag should always be valid, but the fallback should preserve it:

```ts
try {
  const formatLocale = new Intl.Locale(state!.formatLocale || state!.locale!).toString()
  return { ...prefs, locale: state!.locale as Locale, formatLocale }
} catch {
  return { ...prefs, locale: state!.locale as Locale, formatLocale: state!.locale as string }
}
```

### 3. Non-blocking — native placeholder handling diverges from UI and CI

[native-localization.js](/Users/akiralam/code/ax-coder-old/desktop/packages/electron/src/native-localization.js), `createNativeLocalizer`.

UI `formatMessage` and `script/localization-catalog.ts` both `trim()` placeholder names and UI preserves the placeholder for `null/undefined`. Native does neither: `{ count }` won't match, and `null` renders as `"null"`. Align it:

```js
return message.replace(/\{([^{}]+)\}/g, (match, raw) => {
  const name = raw.trim()
  const value = Object.hasOwn(params, name) ? params[name] : undefined
  return value === null || value === undefined ? match : String(value)
})
```

### 4. Non-blocking — controller init doesn't survive a throwing `read()`

[localization.mjs](/Users/akiralam/code/ax-coder-old/desktop/shared/localization.mjs), `createLanguageController`.

`normalizePreferences(read())` has no `try/catch`, while the renderer wraps its storage read. If main's `read` throws on corrupt JSON instead of returning `undefined`, startup crashes. Harden:

```js
let preferences
try { preferences = normalizePreferences(read()) }
catch { preferences = normalizePreferences(undefined) }
```

(Main's `read` implementation wasn't in scope; this only matters if it can throw.)

### 5. Non-blocking — `conversationInstruction` trusts an unchecked manifest table

[localization.mjs](/Users/akiralam/code/ax-coder-old/desktop/shared/localization.mjs).

`isLocale` checks `manifest.labels`, but the template interpolates `manifest.conversationNames[locale]`. A locale present in one table but missing in the other renders `"in undefined"`. Guard:

if (!isLocale(locale) || typeof manifest.conversationNames[locale] !== "string") return undefined
