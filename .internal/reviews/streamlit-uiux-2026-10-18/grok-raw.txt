**Fact:** official docs show Streamlit can stream (`st.write_stream`) and rerun a portion (`st.fragment`, including `run_every`). Forms batch submission. Session State is per WebSocket and resets on reload; it is not durable portfolio storage. Community Cloud embeds public apps and explicitly does not officially support private-app embedding. ### UX critique

**Allow vs once.** **Fact:** `RequestActionCard` labels the button with `notificationCenter.allow` and calls `respondToPermission(..., "once")`. The comment states cross-session surfaces send once; standing grants stay on the in-session card. Sending once is specified. **Hypothesis:** the visible word is bare “Allow,” so people infer a standing grant. The locale catalog is not here, so that misreading is not proven. Change copy, and keep the payload `"once"`.

**Busy and toasts.** **Fact:** `disabled={busy}` applies during `run`; `respondingRef` drops a second call; failures go to `toast.error`. **Overstatement:** this is an in-flight lock on this card, not the supervision “pending” state locking the product. **Hypothesis:** a toast is easy to miss. This snippet does not show the card disappearing on failure.

**Peek.** **Fact:** `MissionControlPeek` uses `max-h-80` and `pl-36`. The 420/760/1440 harness renders `MissionControlRow` and, for permission, `RequestActionCard` directly. It does not mount the peek, so those widths say nothing about it. **Hypothesis:** `pl-36` (9rem) crowds a narrow peek. Unverified.

**Review.** **Fact:** `deriveSupervisionState` maps `uncommitted` to `"review"` after permission, question, and running (`busy` or `retry`). The harness string “Review changes” is fixture copy. The state means uncommitted work. It does not mean tests passed. Shipping copy that claims test success is a **hypothesis**; those strings are not in this packet.

**Already shipped.** Inspector labels exist and default to `inspectorLabels: false`. This excerpt shows plan, context, wiki, and terminal; the prior count of eight tools stands as prior evidence. Main navigation, scope disclosure (two patterns / 160 characters, then expand, with `aria-expanded`), six state labels/icons/colors, container-responsive board rows, density, and reduced motion are present. Matching fixture hashes are not a native end-to-end run and not a screen-reader pass.

### Improvement plan

Preserve once, reject, answer, dismiss, no standing grant on this card, `respondingRef`, `mountedRef`, agent access defaulting off, and `t()` for all new copy.

1. **Once-disclosure.** Point the cross-session allow control at copy that states a single grant, in every shipped locale. **Acceptance:** the accessible name states one-time allow; the call remains `"once"`; deny still sends `"reject"`; a second click while busy does not send; always-grants stay on the in-session card.
2. **Failure stays on the card.** Keep the toast if wanted, and show the error on this card. **Acceptance:** a rejected response re-enables the buttons, shows the error in the card, and allows one later retry; unmount during the request does not `setBusy` after unmount.
3. **Peek fixture.** Mount real `MissionControlPeek` at 420px and at a comfortable width. **Acceptance:** no horizontal clip; the gutter tracks the row without fixed padding wider than the column; scroll still reaches open-session and the request actions; compact and full density still render.
4. **Review copy audit.** Leave the six-state derivation unchanged. **Acceptance:** priority stays permission/question, then running, then error, then uncommitted; locale strings for `review` describe uncommitted changes and do not say tests passed or approved.
5. **Accessibility, still unproven.** Specify names, focus order, and busy/error announcements, then run a screen reader on the real Electron view. **Acceptance** is that run’s notes. This discussion does not satisfy it.

Do phase 1 first. It can change a trust decision. Hold 2–5 behind the release-evidence queue. Do not restyle the board while fixing the peek.

### Streamlit spike

**Go** only if a written requirement names the audience and a job the desktop and shared web UI cannot do, the spike is read-only on the pinned public SDK, it ends in a decision record within three days, and the owner may kill it. Non-goals: installs, spawned processes, port scans, secrets, WebMCP inheritance, Session State as the portfolio store, and any production or private-embed claim.

**Defer** A, B, D, and C’s launch recipe. A generic “open this local URL” action waits for a real request.

### Strongest counterargument

A Python analyst might need a read-only board next week. `st.fragment` and `st.write_stream` could show runtime status in days, while remote deployment and auth for the shared React web UI are not established as qualified. That fails on this evidence. No such audience is named. Streamlit does not qualify auth or private embedding either. A second client would still owe once-only approvals and the signed runtime boundary. The demo is the cheap part. The second product is the expensive part.
