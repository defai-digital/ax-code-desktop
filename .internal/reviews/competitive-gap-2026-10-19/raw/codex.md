**Ranked proposals**

Impacts are estimated changes to the relevant **/10 criterion**, overlap, and are not additive. A revised weighted total would require the original weights and measured evidence.

1. **Consolidate worktree execution — both; L; Architecture +1.** Extend `R/ax-code/src/worktree/index-impl.ts` and server schemas for Desktop’s existing-branch, start-ref and bootstrap needs; replace Desktop service execution with SDK adapters. **Contract:** validated requests, operation identity and bootstrap status. **Dependency:** runtime/SDK release first. **Risk:** migration and recovery parity.

2. **Unify event semantics — both; M; Architecture/Testing +0.5–1.** Replay identical reconnect, duplicate-delta, child-request and deletion traces through `R/sdk/js/src/headless/projection.ts`, runtime projection and `D/ui/src/sync/event-reducer.ts`. **Contract:** documented event/version semantics; keep display state local. **Dependency:** agreed conformance cases. **Risk:** intentional differences mistaken for defects.

3. **Add critical user-journey verification — both; M; Testing +1.** Add Desktop `ui/e2e/` and rendered TUI fixtures for switching, child approvals, reconnect, review and keyboard/mouse focus. Replace selected source guards with behavior checks. **Contract:** existing APIs. **Dependency:** deterministic fixtures, #2. **Risk:** flaky timing and screenshot noise.

4. **Make Electron hardening explicit — ax-code-desktop; M; Security +0.5.** Update `webview-policy.js` and renderer protocol; explicitly sandbox every renderer, remove inline-script dependence, investigate disabling RunAsNode after launcher separation. **Contract:** none. **Dependency:** packaged launcher compatibility checks. **Risk:** preload, CSP and CLI startup regressions.

5. **Introduce validated IPC and real module boundaries — ax-code-desktop; L; Architecture +1.** Add proposed `electron/src/ipc/{contract,handlers,client}.ts`; migrate from the current allowlist incrementally. Extract lifecycle, windows and updater from `main.js`; split chat/files by responsibility. **Contract:** Desktop-local schemas only. **Dependency:** #3. **Risk:** compatibility during mixed JS/TS migration.

6. **Prove release continuity — ax-code-desktop; M; Release +0.5–1.** Extend existing qualification scripts/workflows with exact-inventory signed install, upgrade, rollback and credential/profile receipts. Keep unsupported architectures explicit. **Contract:** none. **Dependency:** native runners/signing access. **Risk:** environment-dependent failures; configuration alone must not count as qualification.

7. **Budget mounted TUI content and automate performance gates — both; L; Performance +1.** Add TUI mount-window/backfill controllers beside `routes/session/index.tsx`; retain stable scroll anchors. Add Desktop rendered-session benchmarks and PTY latency/memory workloads. **Contract:** reuse pagination; extend cursor guarantees only where needed. **Dependency:** #2–3. **Risk:** selection, search and undo across unloaded history.

8. **Pop out existing Mission Control — ax-code-desktop; M; Supervision +0.5.** Add a supervisor window host consuming `useSupervisionRows`, working sets and existing request navigation. **Contract:** none initially; any missing execution evidence belongs in runtime summaries. **Dependency:** #2, #5. **Risk:** duplicate subscriptions and disagreement between windows.

9. **Add a terminal supervision workspace — ax-code; M; Supervision +0.5–1.** Add proposed `cli/tui/routes/supervision/` with project grouping, attention-first rows, stale-state indicators and drill-down. **Contract:** reuse session/status/request APIs; add a bounded execution-summary endpoint only if necessary. **Dependency:** #2. **Risk:** accidental creation of a second project registry or desired-state engine.

10. **Build a dedicated TUI review route — ax-code; M; UX +1.** Replace modal-only review with `routes/review/`: file tree, hunk navigation, split/unified layout and explicit source selection. **Contract:** extend runtime diff APIs for unsupported comparison sources; expose through SDK. **Dependency:** #7. **Risk:** expensive diffs and misleading truncated output.

11. **Create a component behavior catalog — ax-code-desktop; M; UX/Testing +0.5.** Add stories and visual fixtures for supervision rows, permission cards, empty/error states and narrow layouts; fix untranslated copy in touched surfaces. **Contract:** none. **Dependency:** #3. **Risk:** broad redesign or translation churn exceeding scope.

12. **Add task-source adapters selectively — both; L; Breadth +0.5.** Add Desktop adapters for the most requested Jira/Linear/GitLab workflow, normalized ticket references and launch actions. **Contract:** runtime receives source metadata and execution requests; Desktop owns task/project UX. **Dependency:** #1 and credential-provider integration. **Risk:** API drift and credential leakage.

13. **Expose a bounded TUI extension API — ax-code; L; Breadth/Architecture +0.5.** Add proposed `packages/plugin/src/tui.ts` plus host registration/disposal for commands, read-only slots and tool renderers. **Contract:** versioned UI API; no private-core imports. **Dependency:** #3, scoped key handling. **Risk:** crashes, lifecycle leaks and permission bypass.

14. **Pilot remote supervision before native mobile — both; L; Supervision/Breadth +0.5.** Build a responsive projection of Desktop’s inbox and portfolio. **Contract:** runtime owns authenticated execution reads, scoped commands, operation IDs and replay protection; Desktop owns registry/desired state. **Dependency:** #2, #4, #8. **Risk:** remote authority and approval freshness; begin with read-only monitoring.

**Sequencing**

- **Next two weeks:** establish #1’s contract inventory; complete #2’s initial conformance matrix; implement the smallest #3 journeys; explicitly sandbox renderers; assemble #6’s evidence checklist. Use these findings to establish a reproducible score baseline.
- **Next six weeks:** release runtime and SDK changes for #1 before Desktop migration. Deliver bounded transcript work and review APIs before consuming them in clients. Complete #3–8, then terminal supervision and review (#9–10).
- **Later:** component catalog expansion, customer-led adapters, extension API and remote pilot (#11–14). New architectures and native mobile follow demonstrated demand and qualification.

I would explicitly avoid copying Orca’s combined desktop/orchestration ownership: its [runtime worktree implementation](/Users/akiralam/code/ax-code-desktop/.internal/reference/orca/src/main/runtime/runtime-local-git-worktree-create.ts) belongs in **ax-code** under your boundary. Also avoid adopting OpenCode’s entire Effect stack merely to obtain [validated RPC](/Users/akiralam/code/ax-code-desktop/.internal/reference/opencode/packages/desktop/src/shared/ipc-rpc/files.ts); schema validation and layering can be introduced incrementally.

Do not copy arbitrary UI-plugin authority, native mobile scope, or optimization machinery wholesale. OpenCode’s [plugin host](/Users/akiralam/code/ax-code-desktop/.internal/reference/opencode/packages/tui/src/plugin/api.tsx), Orca’s [companion](/Users/akiralam/code/ax-code-desktop/.internal/reference/orca/mobile/README.md), and OpenCode’s [virtualizer](/Users/akiralam/code/ax-code-desktop/.internal/reference/opencode/packages/app/src/session/timeline/virtualizer.tsx) are useful design references; AX needs bounded contracts, demonstrated demand and measured bottlenecks before adopting their complexity.
