# Gap review: AX Code vs Orca and OpenCode

Read-only review. No files changed, no builds or tests run. All claims below cite inspected paths.

## Corrections to the prior scoring

The prior Desktop findings are mostly accurate, with four corrections:

1. **Large files: 64, not 58** (src only, excluding `node_modules`). Top offenders confirmed: `desktop/packages/web/server/lib/git/service.js` (5,049 lines), `desktop/packages/ui/src/components/chat/ChatInput-impl.tsx` (4,903), `desktop/packages/ui/src/components/views/FilesView-impl.tsx` (3,930), `desktop/packages/electron/src/main.js` (3,826). The `-impl` split is indeed cosmetic: 14 `*-impl` files, e.g. `ChatInput.tsx` is the single line `export { ChatInput } from "./ChatInput-impl"`.
2. **Electron main window lacks `sandbox`**, confirmed: `desktop/packages/electron/src/webview-policy.js` `createDesktopRendererWebPreferences()` sets `contextIsolation: true`, `nodeIntegration: false`, `webviewTag: true`, but no `sandbox`. Mitigation exists and deserves credit: `applyDesktopBrowserWebviewPolicy()` forces `sandbox: true` on guests and strips preload. OpenCode sets `sandbox: true` on the main window itself (`packages/desktop/src/main/windows/early.ts`, `appearance.ts`).
3. **CSP confirmed weak**: `desktop/packages/web/server/lib/security/response-headers.js` sends `script-src 'self' 'unsafe-inline' 'unsafe-eval'`. `runAsNode: true` confirmed in `electron-builder.yml`, with a documented reason (packaged desktop CLI uses the Electron binary as Node launcher) — a real constraint, not sloppiness.
4. **Platform claim is stale**: `electron-builder.yml` already defines Linux AppImage/deb targets alongside macOS arm64-only and Windows x64-only. The gap is signed/qualified release evidence (per `AGENTS.md` ADR-012, updater cutover still gated on signed install/upgrade/rollback receipts), not missing targets.

Also understated in AX's favour: Desktop already has a TanStack-virtualized message list (`MessageList-impl.tsx`), a supervision layer (`ui/src/components/supervision/MissionControl.tsx`, `NeedsYouPopover.tsx`, `SinceYouLeftStrip.tsx`), GitHub integration (`web/server/lib/github/`), worktree creation (`NewWorktreeDialog.tsx`, `web/server/lib/git/worktree-bootstrap-generation.js`), 15 locales, and ~750 test files. The deficit is depth and verification, not absence.

## 5. Explicitly do NOT copy

- **Orca's ~700-e2e breadth as a target number.** Copy the gating pattern, not the volume; AX's 750 unit tests plus 20 good e2e flows beat 700 shallow ones, and Orca's own `config/scripts/` ratchet machinery (a dozen `check:*-ratchet` scripts) is process weight AX doesn't need.
- **OpenCode's Effect in the Desktop main process.** Effect-Schema IPC is good; the Effect runtime dependency and programming model are not justified for a CommonJS Electron layer, and AX runtime policy bars Effect in core without an ADR. Zod (already the runtime standard) gives 90% of the benefit.
- **Orca's worktree-as-*only*-unit.** AX Desktop's portfolio/project registry with desired state is a genuine differentiator (Desktop AGENTS.md boundary); make worktree first-class *within* the project, don't replace the project.
- **OpenCode's 63 locales as a goal.** 15 locales covering AX's actual markets plus quality beats breadth; machine-translated locales create support debt.
- **Orca's mobile full-terminal ambitions** (`mobile-terminal-direct-input-default.md`). Approve-only mobile (#13) captures the supervision value without shipping a terminal to a phone.
- **OpenCode's `mini/` as a separate mode.** AX TUI's supervision answer should be tabs (#8) plus the Desktop pop-out (#5), not a third surface to maintain.
