## Review verdict

Plan is broadly supported by the supplied source. Five claims are unsupported or under-specified — flagged at the end. Consolidation points below reuse existing structures rather than introducing new abstractions.

### 1. Permission card truncation (`RequestActionCard.tsx`)

Confirmed: `MAX_PATTERNS = 2` slices `entry.request.patterns` (line ~60) **and** the result is further truncated (`truncate` in compact, `line-clamp-2` in full). No count is shown.

**Recommendation:** Render `detail` as `firstPattern · +N more` (compute N from `patterns.filter(Boolean).length`). Wrap it in a native `<details>/<summary>` (keyboard-accessible for free): summary = first pattern + explicit total ("5 patterns"); body = all patterns as a `<ul>` of fully wrapped items (not `·`-joined). Keep `Allow once`/`Deny` outside the disclosure. Keep question-card behavior untouched (inline options only when `isInlineAnswerableQuestion`; dismiss otherwise).

**Pitfalls:** (a) zero patterns after `filter(Boolean)` → hide the disclosure, keep current empty state; (b) add `stopPropagation` on the `<summary>` — in Mission Control peek/popover contexts ancestors may be click targets; (c) don't gate Allow/Deny behind expansion; (d) the existing `busy`/`mountedRef` guards already handle double-submit and unmount races — a disclosure state reset on unmount is acceptable; (e) don't auto-expand: "expose before approval" is satisfied by count + one keystroke, not by forced expansion.

**Tests:** count text appears iff patterns > 1; disclosure contains every pattern verbatim when 3+ patterns; summary collapses when expanded→Allow clicked mid-flight (buttons disabled via `busy`, single `respondToPermission` call — assert with a spy); unmount while busy does not throw; `<summary>` click does not trigger an ancestor handler.

### 2. Shared status presentation

The inconsistency is real and the proposal fixes it: `MissionControlRow.STATE_META` maps review→info (`file-check`), running→success pulse; `MultiRunCompare.STATE_TONE` maps review→**success**, running→**info**. Adopt one `supervisionStatePresentation(state)` returning `{ icon, statusVar, labelKey }` (warning/error/info/success/muted per plan) and derive both the pill (border+text) and badge (bg tint) classes from `statusVar`. Preserve distinct icons for permission (`shield-warning`) vs question (`question`) — tone alone must not merge them.

**Pitfalls:** (a) this deliberately changes MultiRunCompare's review/running colors — an intentional visual change, note it in the commit; (b) Mission Control "running" is a pulse dot, not an icon — the shared module needs both shapes; (c) i18n label keys already differ (`supervision.state.*` vs `supervision.missionControl.state.*`) — share the key map or keep both, don't regress copy.

**Tests:** for each state, both components emit the same `--status-*` variable; review=info, running=success; question and permission remain visually distinct.

### 3. Header primary navigation

The excerpt already has separators (`HEADER_ACTION_SEPARATOR_CLASS`) and a `data-header-panels` group; Mission Control's toggle is already labeled (`label={t("supervision.missionControl.title")}`). **True duplicate found:** bottom-terminal toggle exists in both the header panel group and `InspectorRail`'s `TERMINAL_ENTRY` (same `isBottomTerminalOpen` state). Consolidate to one, keep the `toggle_terminal` shortcut. Also note an **icon collision**: header split-pane toggle and rail "context" both use `layout-column` — change one icon even if semantics differ.

**Pitfalls:** preserve `OpenInAppButton` (project context), `WebMcpHeaderButton` (browser), and every `shortcutLabel(...)` in titles/aria-labels; keep `aria-pressed` states sourced from the same stores so rail/header stay in sync; do not add "session workspace / review-changes" header actions without acknowledging they are **new** controls (see unsupported claims).

**Tests:** toggling rail terminal reflects in header `aria-pressed` and vice versa; `toggle_terminal` still fires after consolidation; group ordering assertions on `data-header-panels`.

### 4. Mission Control density/responsiveness

Rows are fixed-column (`w-28` state, `w-36` project `hidden sm:block`, `w-32` evidence, `w-16` age, all `shrink-0`) — at narrow widths only the title shrinks. Use a container query (`@container`) on the row wrapper: below a container threshold, switch to a two-line layout (line 1: state pill + title + primary action; line 2: project · evidence · age · compare · remove). Density prop (`comfortable | compact`) adjusts `py`/gap only.

**Pitfalls:** (a) keyboard nav relies on `role="grid"` + `aria-activedescendant` with stable ids `mission-row-${sessionId}` — the row element must remain the same node across density/responsive switches (CSS-only re-layout, no remount) or focus is dropped; (b) keep `title={row.title}` and the compare/remove handlers with `stopPropagation`; (c) header: replace fixed `h-12` with `min-h-12 flex-wrap` — the tablist already scrolls (`overflow-x-auto`), so verify wrapping doesn't create two competing scroll regions.

**Tests:** at narrow container width project label + primary action remain rendered; density toggle preserves `aria-activedescendant` selection (simulate j/k before/after); create/rename/delete working-set controls reachable when the header wraps to two lines.

### 5. Inspector rail labeled navigation

Current rail: 40px (`w-10`), icon-only buttons with `aria-label`, `aria-pressed`, tooltip, diff badge; terminal after a divider.

**Recommendation:** add a single expand/collapse toggle at the rail top (`aria-expanded`, accessible name, focus ring preserved); expanded width ~w-40 showing icon + text label; persist preference in `useUIStore`. Buttons keep `aria-pressed`; visible labels may replace `aria-label` but keep shortcut text visible (currently tooltip-only — surface it in expanded mode). Auto-collapse when `isMobile` already returns null — also auto-collapse under a narrow viewport width to avoid squeezing chat.

**Pitfalls:** focus stays on the toggle after expand (no focus steal); badge must render in both modes; do not move terminal out of the rail (preserve dock/divider placement); tab order: toggle first, then entries.

**Tests:** expanded shows each label text; toggle has `aria-expanded`; active view shows pressed + label emphasis in both modes; badge visible in both modes; collapsed default width unchanged; expansion does not change which view opens on click.

1. **Live sidebar status tone** — no sidebar source supplied; "share across live sidebar" is unverifiable. Scope finding 2 to MissionControlRow + MultiRunCompare until that source is provided.
2. **"Session workspace / review-changes" header actions** — neither exists in the supplied header excerpt (review-changes lives in the rail). These are new controls, not a clarification; the plan should say so or drop them.
3. **"Titlebar popover / Needs You queue"** usages of `RequestActionCard` — only MultiRunCompare usage is in the snapshot (the doc comment asserts the rest). Tests must not assume props those callers pass.
4. **Grid keyboard model** — supported only by a code comment; the board component owning `aria-activedescendant` is not supplied. Finding 4 tests should target the row contract (stable ids, no remount), not grid internals.
5. **"Consolidate duplicate panel controls"** — only the terminal toggle is demonstrably duplicate in the snapshot; split-pane vs rail-context differ in semantics. Consolidate only the proven pair.

### Global acceptance criteria

No runtime/protocol changes (components and stores only); all existing i18n keys reused or added with `en` entries; existing interactions (allow/deny/answer/dismiss/open, compare, working-set ops, rail toggles, shortcuts) behave identically; new states keyboard-reachable; visual diffs limited to the five findings.
