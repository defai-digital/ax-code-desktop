### P1: none found

Every P1 category was traced to code and held:

- **Credential leak (screen/logs/storage).** One redaction entry point: `webmcp-redaction.mjs:108-219`, consumed by main (`desktop-webmcp-browser.js:410,474,480,484`), catalog projection (`webmcp-catalog-projection.cjs:67-71`), approval card (`PermissionCard.tsx:419,427,433,443,459,468,516`), call strip, recap and checker. No console/logging in any WebMCP electron module. Storage keeps origins only (`useWebMcpBrowserStore.ts:425-502`); receipts stay in memory, keyed `[session, callID]`, capped 256 (`useWebMcpApprovalOutcome.ts:33-57`).
- **Acting on the wrong page/session/project.** `desktop-webmcp-browser.js:230-234,774-784` bind sender, provider, epoch, project and session; `559-563` revalidate generation/origin/frame before a navigation; `1220-1222` reject mismatched session/project handles; `webmcp-view-key.mjs:19-21` cannot collide (validated `ses_…` ids, absolute paths, NUL separator); the page program takes no selector, script or coordinate (`webmcp-page.js:5-13,145-164`) and holds element refs in an isolated world for one read.
- **Acting without approval.** The card is built from call data only (`toolHelpers.ts:484-506`); page hints/description require a matching digest bound to that session **and** origin (`useWebMcpApprovalDefinition.ts:6-10`, `WebMcpApprovalToolInfo.tsx:36-41`); the desktop provider offers no standing grant (`PermissionCard.tsx:210-218`).
- **Losing work/data.** Eviction re-probes after the async check and refuses on stale state (`desktop-webmcp-browser.js:818-834`); explicit close, sign-out and shutdown honour `beforeunload` (`,428-454,` `browser-eviction.js:47-68`), refusal aborts shutdown (`browser-shutdown.js:12-15` → `main.js:1160`). Sign out removes storage only after pages close, and reports `operation-failed` otherwise (`,1124-1134`).
- **False statements.** Transport success ≠ application error (`webmcp-manual-outcome.cjs:27-59`); timeout/cancelled never resolve Completed and get no export (`native-webmcp.js:376-394`, `webMcpDiagnosis.ts:140-143`); a vanished approval reads "no answer was recorded", never timeout or rollback (`useWebMcpApprovalOutcome.ts:20-28`, `WebMcpCallStrip.tsx:63-65`); truncation, catalog caps and stale marks are explicit (`webMcpCatalog.ts:245-271,338-353`); checker exit codes distinguish 1/2/3/64 correctly (`webmcp-check-lib.mjs:121-143` — the empty-catalog message is pushed *after* `incomplete`, so exit 2 is reachable).
- **Hang / unusable pane.** Every wait is deadline-bounded: load (`:520-523`), attach (`native-webmcp.js:112-157`), poll (`:636`), reply POSTs 2 s, eviction probe 250 ms, stop ack 500 ms; a wedged teardown cannot block quit (`,` `desktop-webmcp-browser.js:340-343`); `pool-full` is named with a recovery control (`EmbeddedWebMcpBrowser.tsx:467-474`).
- **Documented flows.** I checked the guide's claims against code — sign-in popups in the isolated profile with agent waits (`:655-663,903-936`), Pages/switcher/revoke, Pause vs Disconnect, 4-view bound, origin-only history, `webmcp:check` options and codes, Copy test / `--run`, schema check vocabulary. All present. Pop-out keeps one browser owner: `SessionGrid.tsx:288` suppresses the page link for a popped slot, and main refuses a second owner (`:805-812`).

### P2s

1. **Off-list enum value submitted while the form shows “—”.** `WebMcpToolPanel.tsx:337-341` maps the select value through `options.indexOf(value)`; a replay whose value is no longer in the enum yields `option--1` (nothing selected), but `webMcpToolForm.ts:169-172` still stores that string, and `:105-127` sends it. Repro: journal row → Replay for a call whose enum member was since removed → form shows blank → Try it → the page receives the hidden value. Impact: a manual run sends data the person cannot see (agent calls unaffected).
2. **A long-poll answer can be dropped.** `desktop-webmcp-browser.js:624-647` + `:741-758`: an attempt aborted at `pollTimeoutMs` may still be answered (the comment acknowledges transports that ignore abort); the settled promise discards it, so that request is never dispatched or replied. Impact: the agent's call waits to its own deadline; no false success.
3. **Unredacted names in checker diagnostics.** `webmcp-check-lib.mjs:117,124` → `webmcp-check.mjs:87` print `requested.name` / expected names verbatim while the report is redacted. Repro: `--run 'sk-…'` `{}`. One-line fix: redact `problem` at print time.
4. **Address draft masking is value-dependent** (`EmbeddedWebMcpBrowser.tsx:505-506`): editing a pasted URL into a partial secret can briefly show it; navigation still uses the real draft by design.
5. **An unconfirmed stop holds admission with no deadline of its own** (`native-webmcp.js:559-570`): a page that never answers leaves later calls at “Native operation is unavailable” until Disconnect.
6. **`forget()` is not defensive** (`desktop-webmcp-browser.js:106-114`): a missing record would dereference `record.sender`. Unreachable today; hardening only.
