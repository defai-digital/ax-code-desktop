## P2 findings (registered, non-blocking)

**P2-1 — Orphan-adoption race can double-adopt a page view.** `desktop-webmcp-browser.js:1148-1155` — Reproduction: window A owns a page; A's owner dies; within the same moment two local desktop windows each send any browser command — both enter the adoption loop, both `await entry.recovery`, both then see `!entry.owner` and call `adopt()` (line 513), rebinding owner/sender twice and leaving a stale `closed` listener on the losing window. When that window later closes, `ownerGone()` (line 528) fires spuriously and can relocate a page the other window is using. Impact is bounded (close paths still honor beforeunload/confirmations; control always follows the last `entry.sender`), so this is wrong-window disruption risk, not silent wrong-page agent action. Fix: serialize adoption per entry (adopt-in-flight marker) and make `adopt()` idempotent.

**P2-2 — Page reads return non-password input values to the agent transcript.** `webmcp-page.js:74-76` — Reproduction: paste a credential-shaped string into a page's search/url/email field, then the agent takes a snapshot; the read outline includes `entry.value = clip(el.value, 100)` for text-like inputs, flowing to the runtime transcript. Desktop's own displays redact it, but the model still receives it. Password inputs are excluded; the same filtering should apply to values that look like credentials. Fix: blank or marker-replace `entry.value` when it matches the credential-shape checks before it leaves the isolated world.
